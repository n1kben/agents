---
name: modeling
description: Explore and test a model of real-world facts. Use when clarifying concepts, rules, states, schemas, records, events, or other representations.
---

Model the facts needed to answer a question. Start with a concrete situation. Ask one question at a time for facts only the user knows, without suggesting an answer. Treat existing language, records, code, and history as evidence, not as truth.

State facts in ordinary language before choosing a representation. Treat each fact as an immutable value with stable meaning. Separate it from assumptions, conclusions, storage locations, and operations. An identity connects a causally related succession of states. A state is the value of an identity at a point in time. Time orders those states; a new state does not alter an old one.

Ask whether two observations concern the same identity, especially when they look similar. Work out relationships, valid values, and context. A schema says what may appear; a particular use says what it requires. Distinguish unknown, absent, and inapplicable when the difference changes an answer.

Test the model with examples and counterexamples. If a case does not fit, revise the model or narrow its context. Compare representations by what they can express, rule out, or forget. Prefer one whose possible values match the valid situations. Keep earlier facts when later questions may need them.

Explain the model through a concrete case. Use pitching when there are representations to compare. Use designing when choosing how to change the world.
