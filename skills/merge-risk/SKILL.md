---
name: merge-risk
description: Assess how risky it is to merge a pull request. Use when asked about a PR's merge risk, and after opening or updating one.
---

Answer: how risky is it to merge this PR?

Separate the risk if merged now from the risk once the code is live.

Weigh how well it's verified, how hard it is to undo, and whether anyone would notice if it broke in production.

List deliberate choices, like keeping old behavior, as questions the user can overrule.

Asking about risk is not approval to merge.
