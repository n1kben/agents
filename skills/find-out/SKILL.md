---
name: find-out
description: Settle an unknown instead of guessing. Use before acting on an assumption, or before asking the user something you could find out.
---

Don't guess, and don't ask the user what you can find out. Ask them only about what they want.

- Investigate how: start where it's triggered and follow each step to what does the work.
- Investigate why: read the history back to where it started. Say "because" only when you can quote the reason.
- Research: go to the primary source for the version in use.
- Spike: run the smallest throwaway test that still looks like the real case.
- Prototype: build three options, one at each extreme of the main tradeoff and one in between. Recommend one and wait for the user to pick.

Investigating and researching change nothing. Spikes and prototypes are throwaway.

Back each claim with what you saw, and mark the rest as guesses.
